## v0：小グリッド・全数評価

**設定**：6×6グリッド、障害物なし、8構成の全数評価、`cost_weight=6.0`

**結果**

| 順位 | 構成 | 成功率 | コスト | 適応度 |
|---|---|---|---|---|
| 1 | torque / noisy / wobbly | 100% | 1 | 81.5 |
| 2 | speed / noisy / wobbly | 100% | 2 | 80.7 |
| 3 | torque / precise / stable* | 100% | 3 | 71.9 |
| … | | | | |
| 8 | speed / precise / stable | 100% | 6 | 58.3 |

**勝者**：`torque / noisy / wobbly`（**一番安い構成**）

### 分かったこと

- 淘汰は「一番良い部品」ではなく「**ちょうど足りる、一番安い部品**」を選んだ
- 高性能な部品はオーバースペックになり、コストの分だけ損をした

### 問題点（重要）

- **8通り全部が成功率100%**
- 性能スコアも 87〜94 の狭い範囲に団子
- → **天井効果**。課題が簡単すぎて、部品の良し悪しが成績に出ていない
- 順位を決めていたのは実質コストだけだった

**結論**：「安い部品が優秀」ではなく「**この課題では部品の差を測れなかった**」が正しい読み方。

## v1：課題を難しくする

**設定**：10×10、真ん中に壁＋1マスの狭い通路、ハザード（−15）配置

**結果**

| 順位 | 構成 | 成功率 | コスト | 適応度 |
|---|---|---|---|---|
| 1 | speed / precise / wobbly | 100% | 4 | 55.7 |
| 2 | speed / noisy / stable | 100% | 4 | 54.8 |
| 3 | speed / precise / stable | 100% | 6 | 50.1 |
| 4 | torque / precise / stable | 100% | 5 | 47.0 |
| 5 | speed / noisy / wobbly | 93% | 2 | 27.6 |
| 6 | torque / noisy / wobbly | **0%** | 1 | −86.7 |
| 7 | torque / noisy / stable | **0%** | 3 | −98.0 |
| 8 | torque / precise / wobbly | **0%** | 3 | −98.6 |

### 分かったこと

- **天井効果は崩れた**（成功率が0〜100%に散らばった）← 狙いどおり
- **v0の勝者（最安構成）が成功率0%に転落**
- トルク型モーターの構成が軒並み壊滅（生き残ったのは precise+stable の1体だけ）

### 当時の解釈

1マスの狭い通路をハザードを避けて抜けるには、1歩ずつしか動けないトルク型は余裕がなく詰む。

### ⚠️ この解釈は後の検証でほぼ否定された（下記参照）

**懸念**：壁の位置も通路の狭さもハザード配置も、全部人間が手で決めている。
「トルク型が詰む形」を無意識に作ってしまった可能性がある。n=1 で一般論は言えない。

## v1-検証：ランダムマップ48枚

**設定**：壁18%・ハザード12%をランダム配置（到達可能性はBFSで保証）、
48マップ × 8構成 = **384試行**、学習5000エピソード / 評価400エピソード

### 結果1：「トルク型全滅」は幻だった

- トルク型構成が成功率0%だったのは **192試行中33回（17.2%）**
- 前回の1枚のマップでは トルク型の 3/4 が 0% だった
- → **あのマップは明らかに極端だった。「全滅する」は取り消し**

### 結果2：部品ごとの効き目（これは本物）

| 部品 | 平均成功率の差 |
|---|---|
| モーター（speed 92.2% vs torque 69.8%） | **22.4 pt** |
| センサー（precise 88.0% vs noisy 74.0%） | **14.0 pt** |
| 安定性（stable 82.1% vs wobbly 79.9%） | 2.2 pt |

**モーター > センサー >> 安定性**。安定性はほぼ意味がない。

### 結果3：トルク型は「ハイリスク」だった

| 構成 | 平均成功率 | 標準偏差 |
|---|---|---|
| speed 系 | 84〜99% | **±5〜35** |
| torque 系 | 52〜94% | **±24〜48** |

トルク型は「弱い」のではなく、**マップによって100%か0%かに割れる**。
平均だけ見ていたら見落とす性質。

### 結果4：「強い身体」と「選ばれる身体」のねじれ

| 評価軸 | 1位 | 回数 |
|---|---|---|
| 成功率のみ（コスト無視） | torque / precise / stable | **45/48** |
| 適応度（コスト込み） | speed / noisy / wobbly | 26/48 |
| | torque / noisy / wobbly | 19/48 |

**最も確実な身体と、淘汰が残す身体は完全に別物。**
淘汰が残すのは「そこそこ動く、安いやつ」。

### 結果5：環境の難易度で答えが変わる

| 難易度 | マップ数 | torque | speed | 差 |
|---|---|---|---|---|
| 易しい（平均成功率80%以上） | 29 | 91.3% | 99.0% | 8 pt |
| 中間（50〜80%） | 15 | 44.0% | 84.3% | 40 pt |
| 難しい（50%未満） | 4 | 11.0% | 72.6% | **62 pt** |

**環境が厳しいほど、良い部品の価値が跳ね上がる。**

→ v0の「安い構成で十分」も、v1の「良い部品が要る」も、どちらも正しかった。**環境が違っただけ**。

### 限界

- 壁18%・ハザード12%という比率は人間が決めた（依然として設計依存）
- 「難しいマップ」の層は **4枚しかない**。結論としては弱い
- 難しいマップで安い構成と高い構成の差が縮むのは、たぶん「難しすぎて全員失敗する」別種の床効果。断定不可

### 次にやるべきこと

難しいマップだけを重点的に増やして、この層を厚くする。

## v2:遺伝的アルゴリズム(GA)の導入

**設定**:部品を6種類×3択 = **729通り**に拡張。GA(トーナメント選択・一様交叉・
突然変異・エリート保存、個体数30×20世代)。729通りは全数評価も可能なので、
**GAの答えを総当たりの正解と突き合わせて検証できる**サイズにした。

追加した部品:バッテリー容量(行動可能ステップ数)、車体重量(軽い=滑る/重い=安定)、
演算装置(状態認識の粒度)。

### 結果1:GAは動いた

集団の平均適応度が 0.83 → 58 と上昇。156回の学習で解に到達(全数729の21%)。
課題の難易度も良好(最高装備100%・最低装備0%)で、天井効果も床効果もなし。

### 結果2:しかし答え合わせで重大な問題が発覚 ⚠️

GAの解を全数評価と突き合わせたところ **148位/729**。しかも**同じ遺伝子なのに
適応度がGA測定72.6・全数測定45.8**と食い違った。

原因を調べた結果:

> **同じ身体でも、乱数シードを変えると成功率が 1% 〜 100% まで振れる**(標準偏差36pt)

つまり1回の評価では「身体の良し悪し」ではなく**「その回の運」を測っていた**。
全数評価の1位に見えた構成も、実は平均28%しかない**まぐれ当たり**だった。

### 結果3:対策を試したが、単純には解決しなかった

| 方式 | 全数での順位(5回実行) | 中央値 | 平均真適応度 | 学習回数 |
|---|---|---|---|---|
| 単純GA(1シード) | 3, 3, 3, 222, 224 | 3 | 48.5 | 110 |
| リサンプリングGA | 2, 8, 120, 156, 194 | 120 | 49.2 | 327 |

リサンプリング(上位個体を毎世代シードを変えて再評価し、まぐれをあぶり出す標準手法)は
**単純GAに勝てなかった**。平均真適応度はほぼ同じで、学習回数は3倍。

仮説:(a) リサンプリングに予算を使うぶん探索回数が減った、
(b) **"正解"とした全数評価(3シード)自体がノイジーで、順位比較が成立していない**。

### 結果4:正解表そのものが信用できなかった

上位・中位・下位を抜き取って12シードで測り直すと、上位陣は軒並み成功率が
10pt前後低下(99%→88%、100%→88%)。典型的な**勝者の呪い**。

- 上位60件を12シードで再測定した確定ランキングでは、**3シード版から平均13.6位・最大50位**変動
- ただし「上位圏 vs 中位圏」の区別は保たれている。壊れているのは上位内の細かい順位のみ

**教訓**:ノイジーな評価では、GAの比較も正解表も、単発では信用できない。

## v2.5:「学習しやすさ」を適応度に入れる

v2の失敗から、重要な発見があった。

> **12シードでも推定値が20〜35ptブレる身体がある。**
> これは測定誤差ではなく、**その身体自体が「学習結果が安定しない身体」**だということ。

確定ランキング上位60件のうち:
- **安定して学習できる身体:19件**(例 `torque/cheap/mid/small/mid/high` 99%±2.1)
- **運任せの身体:16件**(例 `balanced/cheap/stable/small/light/high` 89%±**27.1**)

平均성能は同程度なのに、片方は毎回学習でき、片方は運次第。
**従来の適応度(性能−コスト)はこの差を完全に無視していた。**

### 3軸の評価に拡張

1. **最終性能** … 学習後の成功率(従来)
2. **学習の安定性** … 閾値到達率、複数回学習したときのばらつき
3. **学習速度** … 成功率が閾値(80%)に到達するまでのエピソード数

### 学習速度は独立した軸だった

40件をプロファイルした結果:

- 最終性能と学習速度の**相関係数 = −0.500**(弱い負の相関のみ)
- 学習速度は **888〜2162エピソードで2.4倍の差**。最終性能はどれも79〜100%と同程度
- → **「最終的に強い身体」と「速く学習できる身体」は別物**

順位への影響も明確。`torque/cheap/mid/mid/mid/high` は従来13位 → **2位**に浮上。

### 学習速度の淘汰圧をどう定式化するか

現実で「学習の遅さ」が問題になる理由を2つのパラメータで表現した:

- **patience(忍耐予算)** … 何エピソードまで試行錯誤に付き合えるか
  (開発者の忍耐、プロジェクトに与えられた時間)
- **impatience(焦り係数)** … 予算超過1エピソードあたりの減点
  (周囲の技術革新の速さ。遅れると市場に置いていかれる)

```
fitness = (性能 - コスト×重み) × 到達率 - impatience × max(0, 学習ep - patience)
```

### 結果:忍耐予算が変われば、進化は別の身体を選ぶ

3軸適応度でGAを回した結果:

| シナリオ | 予算 | 勝者 | モーター | バッテリー | コスト | 学習ep |
|---|---|---|---|---|---|---|
| じっくり | 3000ep | torque/mid/wobbly/small/light/high | torque | small | 4.5 | 2800 |
| 標準 | 1500ep | balanced/cheap/wobbly/large/light/low | balanced | large | 3.5 | 1367 |
| 超短期 | 700ep | speed/cheap/mid/large/light/high | **speed** | large | **7.5** | **667** |

**v0〜v2を通じて一度も勝たなかった `speed` モーターが、超短期シナリオで初めて勝った。**

時間制約が厳しくなると、**高価だが学習が速い部品にお金を払う**のが合理的になる。
学習667epは標準シナリオの勝者(1367ep)の半分。

逆に時間に余裕があれば、安い `torque` + 小さいバッテリーでじっくり学習させる方が得。

→ **「役割(ここでは開発時間の制約)に応じて、合理的な部品構成は変わる」**を実データで確認。

### 限界

- プロファイルしたのは **40件のみ**(729通り中)。傾向レベルまでしか言えない
- 12シードでも標準偏差20〜35ptの身体があり、細かい順位は依然信用できない
- `patience` `impatience` の具体的な数値は恣意的に置いたもの。**相対比較にしか意味がない**
- 各シナリオのGA実行は1〜2回。再現性の確認が不十分

### 次にやるべきこと

- プロファイル数を増やす(40 → 100件以上)
- 各シナリオでGAを複数回実行し、勝者の傾向が安定するか確認
- **役割そのものを分ける**(速度重視・安全重視・省エネ)。
  今回は「時間制約」1軸だけだったので、タスクの種類を変えれば
  より明確な「役割ごとの推奨構成表」が作れるはず

## v3:役割ごとの部品選定（役割別GA）

**目的**:ユーザーの最終ゴール「役割に対して、強化学習させやすく合理的な部品構成を選ぶ」の
実装。これまでは課題が「速くゴールへ」1つだけだったので、3つの役割を用意した。

### 役割の定義

役割ごとに、**タスク報酬 R（エージェントが感じるもの）と適応度 F（淘汰の基準）の両方**を変える。

| 役割 | 報酬(step/hazard/goal) | 適応度の重み(時間/ハザード/コスト) |
|---|---|---|
| speed（速度重視） | -1.0 / -3.0 / +20 | 1.0 / 2.0 / 6.0 |
| safety（安全重視） | -0.3 / -40.0 / +20 | 0.15 / 30.0 / 6.0 |
| energy（省エネ） | -2.5 / -10.0 / +20 | 2.5 / 5.0 / 10.0 |

### 結果:役割ごとの推奨部品構成表

| 役割 | 推奨構成 | 再現性 | 成功率 | 歩数 | 被弾 | コスト |
|---|---|---|---|---|---|---|
| **速度重視** | balanced/cheap/wobbly/small/light/high | 3/3 | 100% | **16.9** | 1.30 | 4.0 |
| **安全重視** | **torque/precise/stable**/small/light/high | 3/4 | 98.5% | 23.9 | **0.00** | **7.5** |
| **省エネ** | balanced/cheap/wobbly/small/light/high | 3/3 | 100% | 17.8 | 1.33 | 4.0 |

### 分かったこと

**1. 安全重視だけ、まったく違う身体が選ばれた**

モーター `torque`（1歩ずつ確実）、センサー `precise`（高精度）、安定性 `stable` ——
**3つとも最も高価な選択肢**。コスト7.5は速度重視の約2倍。

その見返りが**被弾0.00**（速度重視は1.30回踏む）。代わりに歩数は16.9→23.9と4割遅い。

→ **「安全のために遅さとコストを買う」というトレードオフを、進化が自分で見つけた。**

**2. 速度重視と省エネが同じ構成に収束した（設計上の反省点）**

省エネの適応度は歩数ペナルティ2.5倍・コスト重み10と厳しくしたが、
結局「速く着けば消費も少ない」ため同じ答えになった。
→ **省エネと速度が本質的に同じ目的になってしまっていた。**
別の指標（例:バッテリー残量、加速回数）で区別する必要がある。

**3. 再現性**

- speed / energy:3/3で完全一致（強い再現性）
- safety:4回中3回が同じ解、1回はGAが局所解に嵌まって失敗（成功率1.5%）
- → **安全役割は探索が難しい**（ハザードを避ける解は狭く、見つけにくい）

## v2.5拡張:プロファイル数を40 → 60件に

### 学習速度と最終性能の相関

| サンプル数 | 相関係数 |
|---|---|
| 40件 | -0.500 |
| **60件** | **-0.296** |

サンプルを増やすと相関がさらに弱まった。
→ **学習速度と最終性能は、より一層「独立した軸」に近い。**

学習速度の範囲も広がった:**688 〜 2729 ep（4.0倍の差）**

### 部品ごとの「学習速度」への影響（60件）

| 部品 | 速い ← → 遅い |
|---|---|
| **バッテリー** | large:1001ep → mid:1384 → **small:1886** |
| モーター | speed:925ep → balanced:1381 → torque:1664 |
| センサー | cheap:1389 → mid:1563 → precise:1715 |
| 車体重量 | light:1394 → mid:1512 → heavy:1777 |
| 安定性 | mid:1424 → stable:1445 → wobbly:1617 |

**バッテリー容量が学習速度に最も効く**（large は small の1.9倍速い）。
1エピソードあたり長く動けるほど、ゴール到達の経験を早く積めるため。

### 部品ごとの「学習の安定性」への影響（ばらつきsdの平均）

| 部品 | 安定 ← → 不安定 |
|---|---|
| モーター | balanced:8.9pt → torque:15.2 → **speed:28.3** |
| バッテリー | large:9.0pt → mid:9.7 → **small:17.1** |
| 安定性 | wobbly:10.3 → mid:12.6 → **stable:19.0** |
| センサー | cheap:11.4 → mid:12.6 → precise:16.1 |
| 車体重量 | mid:12.2 → light:12.5 → heavy:14.2 |

**面白い逆転が2つ:**

- `speed` モーターは**学習が最も速いが、最も不安定**（28.3pt）。速く学べるが運次第
- `stable`（安定した車体）が**学習の安定性では最下位**（19.0pt）。
  → **車体の物理的安定性と、学習結果の安定性は別物**

### 限界

- プロファイルは60件（729通り中）。まだ全体の8%
- `compute` は上位候補が全て `high` のため比較不能（n=60すべてhigh）
- 役割別GAは各3〜4回のみ。特にsafetyは1回失敗しており、試行回数を増やすべき
- 役割の報酬・適応度の重みは恣意的に設定したもの
- 省エネ役割の設計が失敗しており、再設計が必要

### 次にやるべきこと

- 省エネ役割を速度重視と区別できるよう再設計する
- 役割別GAの試行回数を増やす（特にsafety）
- プロファイル数をさらに増やす（60 → 100件以上）
- 複数マップで役割別GAを回し、マップ依存でないことを確認する
