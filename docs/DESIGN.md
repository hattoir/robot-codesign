# DESIGN —— 設計思想

## この研究が問うていること

強化学習では「報酬関数の決め方」が確立されていない。
人間が手で報酬を設計するのは恣意的では？ という疑問が出発点だった。

そこから考えが移っていき、最終的にこういう問いに落ち着いた：

> **ロボットの「解答」を人間が設計しないと、何が生き残るのか。**

行動（動き方）も、身体（部品構成）も人間は決めない。
人間が決めるのは「課題」だけ。あとは淘汰圧に任せる。

---

## 二層構造

| 層 | 何を決めるか | 誰が決めるか |
|---|---|---|
| 内側 | その身体をどう動かすか | **強化学習** |
| 外側 | どの部品を積むか（身体） | **淘汰 / 進化** |

### なぜ強化学習を組み込むのか

**RL は「その身体の潜在能力を引き出す装置」**だから。

もし動き方を人間が固定していたら、部品を変えても正当に比較できない。
ある部品構成が「ダメ」に見えても、それは動かし方が下手なだけかもしれない。

RL があることで、
- スピード型モーターの身体 → 「2歩進む前提の動き方」を学ぶ
- ノイズだらけのセンサーの身体 → 「多少見間違えても何とかする動き方」を学ぶ

つまり **各身体が最善を尽くした状態同士で比較できる**。

---

## R と F を分ける（最重要）

この研究の背骨。

| 記号 | 名前 | 内容 |
|---|---|---|
| `R` | 報酬 | エージェントが感じるもの。**ノイズありのセンサー越しの、歪んだ世界** |
| `F` | 適応度 | 淘汰の基準。**真の状態で測った、客観的な結果** |

RL は `R` を最大化する。しかし淘汰は `F` で判定する。

生き物と同じで、本人がどう感じていようと、生き残ったかどうかは環境が決める。
ここを混ぜると研究が成立しない。

コード上では：
- `step()` が返す `reward` が `R`
- `evaluate()` が計算するスコアが `F`
- `observe()` がセンサーノイズを入れる境界

## 部品カタログ

| 部品 | 選択肢 | 効果 | コスト |
|---|---|---|---|
| モーター | `torque` | 1歩ずつ確実に進む | 1.0 |
| | `speed` | 2歩進むが、15%の確率で滑る（1歩 or 3歩） | 2.0 |
| センサー | `precise` | 正確に自己位置を認識 | 2.0 |
| | `noisy` | 25%の確率で隣のマスに見間違える | 0.0 |
| 安定性 | `stable` | 指示どおりに動く | 2.0 |
| | `wobbly` | 20%の確率で行動がランダムに化ける | 0.0 |

2 × 2 × 2 = **8通りの身体**。

### 適応度の計算

```
fitness = performance − cost_weight × cost
```

`cost_weight` を変えると「性能とコストの交換レート」が変わり、勝者が入れ替わる。

## 環境

### v0
- 6×6グリッド、障害物なし
- スタート(0,0) → ゴール(5,5)
- 報酬：1歩ごとに −1、ゴールで +10

### v1
- 10×10グリッド
- 真ん中に壁、**1マスだけの狭い通路**
- 通路を外れた位置に**ハザード（−15点）**
- 報酬：1歩 −1、ハザード −15、ゴール +20

### 大規模検証
- 壁18%・ハザード12%を**ランダム配置**（BFSで到達可能性を保証）
- 48枚のマップで同じ実験を繰り返す

## 強化学習の設定

**テーブル型 Q学習**（あえて単純な手法を使っている）

| パラメータ | 値 |
|---|---|
| 学習率 α | 0.2 |
| 割引率 γ | 0.95 |
| ε（探索率） | 1.0 → 0.05 に線形減衰 |
| エピソード数 | 5000（大規模検証） |
| 評価エピソード数 | 400（貪欲方策） |

**なぜ PPO ではなく Q学習か**：
状態空間が小さい（100マス × 4行動）ので、テーブル型で十分。
そして圧倒的に速い。物理シミュレーションに移る v3 で PPO に切り替える予定。

---

## 意図的に守っているルール

1. **一度に一軸だけ自由にする**
   自由度 × 課題の複雑さ × 身体ごとの学習 は掛け算で爆発する。
   課題は単純に保ったまま、身体の自由度で驚きを取りにいく。

2. **「人間のバイアスがゼロ」とは言わない**
   課題も、部品の候補も、シミュレータも、適応度の式も全部こちらが選んでいる。
   手放せているのは "解き方" の設計だけ。正直に「解の設計を最小化した」と書く。

3. **派手な結果が出たら疑う**
   n=1 の実験で一般論を主張しない。必ずランダム化して再検証する。
   （v1でこれを怠りかけて、実際に8割が幻だった）
